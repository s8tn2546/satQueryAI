# SatQuery AI — System Architecture & Data Flow Guide

## 1. High-Level Architecture Overview

SatQuery AI is designed as a **decoupled, 3-tier microservices system**:

```
 ┌─────────────────────────────────────────────────────────────────────────┐
 │                            FRONTEND (React + Vite)                      │
 │   - CesiumJS 3D Globe View           - Glassmorphic Search Composer     │
 │   - Interactive Results & Evidence   - Live Spatial Telemetry HUD       │
 └────────────────────────────────────┬────────────────────────────────────┘
                                      │ HTTP (JSON / Multipart)
                                      ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │                   BACKEND ORCHESTRATOR (Node.js + Express)              │
 │   - Agentic Intent Classifier        - Task Planner & Tool Executor     │
 │   - Input Validation & Guardrails   - Answer Composer & Evidence Layer │
 │   - MongoDB (Tiles, Queries, Cache)  - Session History Manager          │
 └────────────────────────────────────┬────────────────────────────────────┘
                                      │ HTTP (Tool Payloads)
                                      ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │                   ML & GEOSPATIAL SERVICE (Python + FastAPI)            │
 │   - Qwen2-VL Local VLM (VQA/Caption) - Rasterio Multi-Band IO           │
 │   - Band Math (NDVI, NDWI, Area)     - Change & Optical-SAR Fusion     │
 │   - Google Earth Engine (Trend)      - Raster Validation Engine         │
 └─────────────────────────────────────────────────────────────────────────┘
```

---

## 2. Component Interaction & Communication

1. **Frontend ↔ Backend (`http://localhost:5010`)**:
   - `POST /api/images/upload`: Uploads raw TIFF/GeoTIFF raster files. Returns normalized `tile` metadata.
   - `POST /api/query`: Sends natural-language query, `imageRefs` array, `sessionId`, and `roiAttachment` bounds.
   - `GET /api/query/history?sessionId=...`: Retrieves persistent query history for the session.

2. **Backend ↔ ML Service (`http://localhost:8080`)**:
   - `POST /validate`: Verifies raster dimensions, band counts, CRS, and modality (optical vs SAR).
   - `POST /vqa`: Invokes local Qwen2-VL model for visual question answering.
   - `POST /caption`: Generates VRSBench-style remote-sensing captions.
   - `POST /ndvi` / `POST /ndwi`: Executes multi-spectral pixel mathematics.
   - `POST /area`: Computes exact surface area in $km^2$.
   - `POST /change`: Computes difference mask between two co-registered scenes.
   - `POST /trend`: Queries Google Earth Engine historical time-series data.

## 3. End-to-End Query Execution Flow

```
[ User Query Input ] ──► [ Backend Intent Classifier ]
                               │
                               ▼ (Task Type: VQA / NDVI / CHANGE / AREA)
                         [ Input Validator ]
                               │ (Verify tile availability & bounds)
                               ▼
                         [ Tool Executor ] ──► HTTP POST ──► [ Python ML Service ]
                                                                   │
                                                                   ▼ (PyTorch / Rasterio)
                         [ Answer Composer ] ◄── Tool Output ──────┘
                               │
                               ▼ (Assemble Evidence, Confidence, Trace)
                         [ Frontend Renderer ]
```

## 4. Trust Layer & Evidence Schema

Every query response generated by the system complies with the strict **Trust Layer Schema**:

- **`answerText`**: Clean, direct natural-language answer.
- **`confidence`**: Normalized score (0.0 to 1.0) derived from spatial co-registration, band match quality, and VLM confidence.
- **`taskType`**: Classified intent (`VQA`, `NDVI`, `NDWI`, `CHANGE`, `AREA`, `TREND`, `OPTICAL_SAR`).
- **`executionTrace`**: Chronological list of steps executed (`intent_classification`, `validation`, `tool_execution`, `answer_generation`).
- **`evidence`**:
  - `tiles`: Metadata of rasters used.
  - `toolResults`: Raw mathematical outputs from ML tools.
  - `isDemoPrecompute`: Flag indicating whether live or fallback data was served.
